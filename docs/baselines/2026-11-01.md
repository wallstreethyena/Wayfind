# Baseline metrics, 2026-11-01

Purpose: a fixed starting line so later improvements can be measured honestly. Read only capture. No product code changed.

Rules used: zero is reported as zero. Nothing is estimated. Anything not measured is listed under "Not measured" with the reason.

## Windows (UTC, fixed cutoff so every query is repeatable)

| Name | Start (inclusive) | End (exclusive) |
|---|---|---|
| 7d | 2026-10-25 18:15:00 UTC | 2026-11-01 18:15:00 UTC |
| 28d | 2026-10-04 18:15:00 UTC | 2026-11-01 18:15:00 UTC |

The PostHog project timezone is UTC. The cutoff is mid day on 2026-11-01, so the last day is partial. Numbers can drift by a few events if the same query is rerun, because PostHog ingestion is still settling (for example `boo_companion_shown` read 2523 in one run and 2524 in the next).

### Client event filter ("clean traffic"), used for every PostHog number unless stated

```sql
timestamp >= <window start> AND timestamp < toDateTime('2026-11-01 18:15:00')
AND properties.$host = 'www.gowayfind.com'
AND ifNull(toString(properties.$internal_or_test_user),'') != 'true'
AND ifNull(toString(properties.is_test),'') != 'true'
AND ifNull(toString(properties.wf_test),'') = ''
AND ifNull(toString(properties.$virt_is_bot),'') != 'true'
AND ifNull(properties.$geoip_postal_code,'') != '34219'   -- project test account filter (owner home ZIP)
AND ifNull(properties.$geoip_city_name,'') != 'Ashburn'   -- project test account filter (data center traffic)
```

What it removes, measured on `$pageview` over 28d: localhost and `*.vercel.app` preview hosts, the blog host (`blog.gowayfind.com`, 75 pageviews, reported separately), events flagged `is_test` / `wf_test` (the `prod_verify_*` probes), PostHog bot flags (79 pageviews), and the two project test account filters (880 pageviews over 28d, 764 users).

"Users" means distinct `person_id`. These are mostly anonymous browser identities, so one person on two devices counts twice.

### Server side events filter

## 7. Returning visitors

Clean traffic, `$pageview`, www host.

Share of 28d users seen on 2 or more distinct UTC days:

```sql
SELECT countIf(c>=2), count(), round(100*countIf(c>=2)/count(),2)
FROM (SELECT person_id, uniq(toDate(timestamp)) c FROM events WHERE event='$pageview' AND <clean traffic filter, 28d> GROUP BY person_id)
```

Result: **130 of 8,716 users = 1.49%**.

Weekly buckets inside the 28d window (week 1 starts 2026-10-04 18:15 UTC, each bucket is 7 days):

| Week | Users | Seen in an earlier week of the window | Seen on 2+ days within that week |
|---|---|---|---|
| 1 (10-04 to 10-11) | 711 | 0 (first week, none possible) | 20 |
| 2 (10-11 to 10-18) | 2,015 | 16 | 21 |
| 3 (10-18 to 10-25) | 3,093 | 22 | 28 |
| 4 (10-25 to 11-01) | 2,960 | 26 | 41 |

Week 4 is the 7d window. Returning users in week 4 (seen in an earlier week) = 26 of 2,960 = 0.88%. Caveat: identities are anonymous browser ids, so cleared cookies or a second device look like new users, which understates true returning behavior. ## Not measured, and why

1. **`christmas_filter_applied` by `filter_id`:** the event and the `filter_id` property do not exist in PostHog and are not emitted by the repo. Value reported as 0. A breakdown needs the event to be instrumented first.
2. **`commerce_cta_clicked` with `surface='christmas_tickets'`:** no such surface value exists in either window (0). Christmas ticket clicks are therefore not attributable to that surface name; check the surface names the Christmas page actually emits before using it as a future baseline.
3. **`content_save` by `content_type` other than `event`:** none fired in 28d.
4. **Median create to READY for all 91 READY deployments:** the Vercel list call returns no ready timestamp, and reading one deployment at a time for 91 deployments was not done. Only the 11 most recent are reported, labeled as a sample (n = 11). Queue wait was measured for the same 11.
5. **Whether the Vercel runtime error `count` is strictly inside the 7d window:** the tool does not say; totals are reported as returned.
6. **Photos as a visitor sees them:** only `wf_events.hero_image` was counted, not photos pulled from the linked place row.
7. **City level place counts:** `wf_inventory.locality` is blank for 85.5% of rows and there is no other city column, so a true by city ranking is not possible. `metro` is given instead.
8. **True unique people:** PostHog `person_id` for anonymous traffic is per browser, so unique user figures overstate people and returning visitor rates understate loyalty.
9. **Revenue or commission outcomes:** not part of this capture. A partner id or a redirect only shows intent, not credited commission.
